# 前言

## 本书目标与读者

如果你正在翻阅这本书，大概率已经写过不少 Swift 代码——或许是一个 iOS 应用，或许是一个服务器端项目，又或者是某个嵌入式系统上的 Swift 程序。你已经掌握了基础语法：知道 `let` 和 `var` 的区别，会用 `if let` 解包可选值，也写过几个协议和泛型。但是，你可能总觉得对这门语言的理解还停留在"会用"的层面，而未能触及"为什么这样设计"的深度。

本书的目标，正是带你跨过这道门槛。

我们面向的是**已经掌握 Swift 基础语法**、**希望深入理解其核心设计理念**的开发者。这里没有"什么是类"、"如何定义函数"这类入门级内容。相反，我们会从以下三个层次展开讨论：

1. **设计决策层**：Swift 的每个特性背后都有明确的设计取舍。为什么 Optional 是枚举而非特殊的编译器魔法？为什么初始化有两阶段安全约束？不理解这些问题，你就无法真正驾驭这门语言。
2. **内部机制层**：值类型和引用类型的内存布局差异是什么？闭包捕获变量的底层原理是什么？`await` 在运行时如何暂停和恢复执行？这些知识决定了你能否写出高性能的 Swift 代码。
3. **最佳实践层**：结合前两个层次的理解，推导出在实际工程中应该遵循的原则。何时用结构体、何时用类？协议扩展有哪些陷阱？如何设计一个既安全又灵活的 API？

## 如何阅读本书

本书共九部分 22 章，外加四个附录。

**第一部分到第五部分**是核心内容，涵盖了 Swift 的类型系统、协议导向编程、值类型、控制流和函数式特性。这些章节之间有较强的依赖关系，建议**按顺序阅读**。尤其是第 2 章（可选值）和第 3 章（初始化与解构），它们是理解后续所有内容的基础。

**第六部分到第七部分**涉及内存和并发，相对独立。如果你正在优化现有项目的性能，或者准备将项目迁移到 Swift 的结构化并发模型，可以提前阅读这些章节。

**第八部分到第九部分**是工程实践专题。建议在读完前五部分后，结合实际项目需求阅读这些章节。

每一章都包含大量代码示例。我们强烈建议你：

1. **动手输入示例代码**，而不是仅仅阅读。肌肉记忆对理解语言的细节有不可替代的作用。
2. **修改示例代码并观察结果**。每个示例都有刻意设计的边界情况，尝试修改代码看看会发生什么，这是最好的学习方式。
3. **完成每章末尾的思考题**（如果有的话），它们帮助你检验是否真正理解了核心概念。

## Swift 设计哲学：安全、高效、表达力

Swift 的设计目标从一开始就非常清晰：创造一门既具有脚本语言的表达力，又具备系统级性能和安全性的语言。这三大设计哲学贯穿了本书的所有章节。

### 安全（Safety）

安全是 Swift 最核心的设计目标。它体现在多个层面：

**类型安全**：Swift 的类型系统非常严格。任何类型不匹配都会在编译时被捕获，而不会留到运行时崩溃。Optional 类型从根本上解决了空指针问题——一个非可选类型保证永远不会是 `nil`，编译器会强制执行这个保证。

**内存安全**：Swift 的自动引用计数（ARC）自动管理内存，消除了手动管理内存带来的 crash 和泄漏。同时，Swift 通过初始化两阶段检查和独占内存访问规则，在编译时就阻止了大量潜在的内存错误。

```swift
// 编译器保证：非可选类型永远不会是 nil
let name: String = "Swift"  // 永远安全
// let empty: String = nil  // 编译错误！

// 可选类型强制你显式处理空值
let optionalName: String? = nil
// print(optionalName.count)  // 编译错误：必须解包
if let name = optionalName {
    print(name.count)  // 安全
}
```

### 高效（Performance）

Swift 的设计追求"零开销抽象"——高级语言特性不应该带来运行时性能损失。

**值类型优先**：Swift 默认使用结构体而非类，这意味着大多数数据操作发生在栈上而非堆上，避免了引用计数的开销和内存分配的开销。

**编译优化**：Swift 使用 LLVM 编译器后端，可以进行深度优化。泛型特化（Specialization）、函数内联（Inlining）、写时复制（Copy-on-Write）等技术，让高级抽象编译为接近手写优化的机器码。

```swift
// 高级抽象，但编译器会优化为高效的机器码
let numbers = [1, 2, 3, 4, 5]
let result = numbers
    .filter { $0.isMultiple(of: 2) }
    .map { $0 * $0 }
// 编译器可能将链式操作融合为一次遍历
```

### 表达力（Expressiveness）

Swift 的语法设计让代码既能清晰地表达意图，又保持简洁。

**协议导向编程**：Swift 用协议（Protocol）替代了传统的继承体系，让类型之间的关系更加灵活和清晰。协议扩展（Protocol Extension）使得我们可以为任意类型添加默认实现，实现了真正的面向协议编程。

**声明式语法**：模式匹配、可选链、属性包装器等特性，让代码更加声明式而非命令式，提高了代码的可读性和可维护性。

```swift
// 表达力：用声明式语法描述意图
enum TrafficLight {
    case red, yellow, green
}

func action(for light: TrafficLight) -> String {
    switch light {
    case .red:
        return "停止"
    case .yellow:
        return "准备"
    case .green:
        return "通行"
    }
}

// 属性包装器：复用逻辑
@propertyWrapper
struct Clamped<T: Comparable> {
    private var value: T
    private let range: ClosedRange<T>
    
    init(wrappedValue: T, _ range: ClosedRange<T>) {
        self.range = range
        self.value = min(max(wrappedValue, range.lowerBound), range.upperBound)
    }
    
    var wrappedValue: T {
        get { value }
        set { value = min(max(newValue, range.lowerBound), range.upperBound) }
    }
}

struct Settings {
    @Clamped(0...100) var volume: Int = 50
}
```

这三大设计哲学——安全、高效、表达力——不是独立的，而是相互交织、彼此成就的。安全的类型系统让编译器可以做出更大胆的优化；表达力强的语法让开发者可以更精确地描述意图，从而让编译器做更多的安全检查。
